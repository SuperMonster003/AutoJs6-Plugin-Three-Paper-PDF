### Введение

******

3-Paper PDF - это PDF-плагин для AutoJs6, а также набор инструментов и просмотрщик PDF, которые работают и без AutoJs6. Он читает сведения, текст, оглавление и встроенные изображения PDF и отрисовывает страницы в изображения; объединяет, разделяет, извлекает, удаляет, переупорядочивает и поворачивает страницы; создаёт PDF из изображений, текста или HTML, а также шифрует и расшифровывает документы.

Обработка выполняется в плагине с помощью `PdfRenderer` из Android и PDFBox-Android на чистом Java, поэтому хост AutoJs6 остаётся лёгким. Скрипты AutoJs6 используют эти возможности через глобальный модуль `pdf`, как и скрипты плагинов Node.js Runtime и Bun Runtime; AutoJs6 открывает пути, переданные скриптами, и передаёт их плагину, поэтому плагину не нужно разрешение на доступ к хранилищу для обработки файлов скриптов. У плагина есть собственный просмотрщик, который открывается из лаунчера, файлового менеджера AutoJs6, команды "Открыть с помощью" в других приложениях или скрипта (`pdf.view`).

> Модулю `pdf` в скриптах AutoJs6 и пунктам файлового менеджера нужен AutoJs6 6.8.1 (внутренняя сборка 6641) или новее; более старые версии AutoJs6 показывают плагин в центре плагинов как несовместимый. Набор инструментов и просмотрщик не зависят от AutoJs6 и работают сами по себе.

### Основные Возможности

******

- Чтение: число страниц, размеры страниц, метаданные, состояние шифрования и разрешения; текст и оглавление (закладки) по страницам; поиск текста с номерами страниц и позициями; список и экспорт встроенных изображений.
- Отрисовка: страницы в объекты `Image` или файлы PNG / JPEG / WebP, по умолчанию 144 dpi, либо по разрешению, масштабу или целевым ширине и высоте.
- Операции со страницами: объединение (с сохранением закладок), разделение, извлечение, удаление, переупорядочивание и поворот страниц; номера страниц начинаются с 1, диапазоны записываются как `'1-3,5,8-'`.
- Создание: изображения в PDF (JPEG встраиваются как есть, без перекодирования), текст в PDF (с выбранным шрифтом) и HTML в PDF (удалённые URL не загружаются).
- Шифрование: открытие зашифрованных документов по паролю, шифрование AES-256 с настройкой разрешений, снятие шифрования.
- Просмотрщик: непрерывная прокрутка, масштабирование двумя пальцами, миниатюры, оглавление, подсветка результатов поиска, переход к странице, ввод пароля и ночной режим; другие приложения могут передать ему PDF через "Открыть с помощью" или "Поделиться"; скрипты могут открыть просмотрщик и получать события смены страницы и закрытия.
- Набор инструментов: 8 инструментов для объединения, разделения, преобразования в изображения, преобразования изображений в PDF, шифрования, расшифровки, извлечения текста и упорядочивания страниц; задачи выполняются по очереди в фоне, а ход выполнения виден в уведомлении; недавние файлы запоминают и файлы, открытые через системный выбор файлов.
- Файловый менеджер AutoJs6: нажатие на PDF открывает его в просмотрщике плагина, причём PDF размером до 512 MiB внутри архивов тоже открываются напрямую; меню предлагает объединение, разделение, преобразование в изображения, извлечение текста, шифрование и снятие пароля.
- OCR: `pdf.text(path, { ocr: true })` распознаёт отсканированные страницы без текстового слоя с помощью установленного OCR-плагина (ML Kit OCR, Paddle OCR или Rapid OCR).
- Node.js и Bun: Node.js Runtime 2.2.0 и Bun Runtime 0.23.0 и новее предоставляют тот же модуль `pdf`; его методы возвращают Promise, а вызовы можно прервать с помощью `signal` или `timeoutMs`.

### Использование

******

1. Скачайте APK со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Paper-PDF/releases) и установите его. Для всех ABI есть один общий пакет.
2. Чтобы пользоваться им в скриптах AutoJs6 или в файловом менеджере, обновите AutoJs6 до 6.8.1 (внутренняя сборка 6641) или новее и убедитесь, что плагин включён в центре плагинов.
3. Чтобы пользоваться встроенным набором инструментов, откройте плагин и по запросу предоставьте доступ ко всем файлам; операциям скриптов это разрешение не нужно.

> Плагин поддерживает устройства с Android 7.0 (API 24) и новее. Для обработки PDF используются только системные API и библиотеки на чистом Java; единственная нативная библиотека входит в Jetpack Compose и выровнена по страницам памяти 16 KB, поэтому один пакет подходит для всех ABI.

### Совместимость

******

- Android 7.0 (API 24) и новее, один пакет для всех ABI; набор инструментов и просмотрщик не зависят от AutoJs6.
- Скрипты AutoJs6 и файловый менеджер: нужен AutoJs6 6.8.1 (внутренняя сборка 6641) или новее.
- Приложения, упакованные AutoJs6: должны быть упакованы AutoJs6 6.8.1 (внутренняя сборка 6641) или новее, а на устройстве, где они работают, должен быть установлен этот плагин; при упаковке добавляется разрешение `org.autojs.plugin.pdf.permission.RUNTIME`, поэтому менять `project.json` не нужно (проект Node.js объявляет `files`, проект Bun объявляет `pdf.control`).
- Node.js: нужен плагин Node.js Runtime 2.2.0 или новее, модуль загружается через `require('autojs6:pdf')`; проект объявляет `files` в `node.permissions` файла `project.json`, а также `files.write` для записи файлов, `ocr` для распознавания текста и `ui` для открытия просмотрщика.
- Bun: нужен плагин Bun Runtime 0.23.0 или новее (Android 13 и новее), модуль доступен через `host.pdf`; включите `pdf.control` на экране настроек Bun Runtime, а для распознавания текста также `ocr.control`.
- OCR: для распознавания отсканированных страниц нужен OCR-плагин (ML Kit OCR, Paddle OCR или Rapid OCR); без него распознавание отсканированных страниц завершается ошибкой `OCR_UNAVAILABLE`, остальные возможности не затрагиваются.

### API Скриптов

******

Скрипты AutoJs6 используют эти возможности через глобальный модуль `pdf` (также доступен как `$pdf`; полное описание: [Документация AutoJs6 > PDF](https://docs.autojs6.com/#/pdf)):

```javascript
let info = pdf.info("./book.pdf");
console.log(info.pageCount, info.title);
let pages = pdf.text("./scan.pdf", { ocr: true });
let img = pdf.render("./book.pdf", 1, { dpi: 200 });
images.save(img, "./page-1.png");
img.recycle();

let doc = pdf.open("./book.pdf", { password: "1234" });
let hits = doc.search("AutoJs6");
doc.save("./book-first-3.pdf", { pages: "1-3", rotate: { pages: "2", degrees: 90 } });
doc.close();

pdf.mergeAsync(["./a.pdf", "./b.pdf"], "./ab.pdf", { onProgress: (p) => console.log(p.stage, p.percent) })
    .then((r) => console.log(r.path, r.pageCount));

pdf.fromImages(["./1.jpg", "./2.png"], "./album.pdf", { pageSize: "A4", fit: "contain", margin: 24 });
pdf.fromText(files.read("./notes.txt"), "./notes.pdf", { fontSize: 14 });
pdf.fromHtml("<h1>Report</h1><p>Hello</p>", "./report.pdf");
pdf.encrypt("./report.pdf", "./report-locked.pdf", { userPassword: "open", ownerPassword: "owner", permissions: { print: true, copy: false } });

let session = pdf.view("./book.pdf", { page: 5, search: "AutoJs6" });
session.on("page", (e) => console.log("page", e.page));
session.on("close", () => console.log("closed"));
```

В Node.js и Bun одноимённые методы возвращают Promise (в Bun они доступны через `host.pdf`):

```javascript
"nodejs";
const pdf = require("autojs6:pdf");

(async () => {
    const { texts, pages } = await pdf.text("./book.pdf", { pages: "1-3" });
    console.log(pages, texts[0]);
    const merged = await pdf.merge(["./a.pdf", "./b.pdf"], "./ab.pdf", {
        displayNames: ["Part A", null],
        timeoutMs: 60000,
    });
    console.log(merged.path, merged.pageCount);
})();
```

- Удобные методы, например `pdf.info` / `pdf.text` / `pdf.render` / `pdf.merge` / `pdf.split` / `pdf.fromImages`, открывают и закрывают документ при каждом вызове; `pdf.open(path, options)` возвращает `PdfDocument`, который использует одно открытие для нескольких операций; один скрипт может держать открытыми не более 8 документов.
- У каждого метода есть блокирующая форма и форма `xxxAsync`, возвращающая Promise, с одинаковыми аргументами и результатами; блокирующую форму нельзя вызывать в потоке интерфейса (ошибка `INVALID_ARGUMENT`), поэтому скрипты с интерфейсом используют `xxxAsync`; методы, записывающие файлы, принимают `onProgress`, а у их Promise есть `cancel()`; отмена или остановка скрипта никогда не оставляет недописанный файл.
- `displayNames` у `pdf.merge` задают имя закладки для каждого входного файла: `null` берёт имя файла (без `.pdf`), а пустая строка или строка из пробелов берёт заголовок документа (`Document <n>`, если его нет); параметры больше примерно 63 KiB завершаются ошибкой `LIMIT_EXCEEDED`, и ничего не записывается.
- `pdf.fromHtml` по умолчанию выполняет скрипты страницы, а `javaScript: false` их отключает; внешнее содержимое не загружается: на сетевые запросы возвращается пустой ответ, и они записываются в `warnings`.
- `pdf.view(path, options)` открывает просмотрщик и возвращает `PdfViewSession` с событиями `page` / `close` и методами `goTo(page)`, `state()` и `close()`; если AutoJs6 не на переднем плане (на Android 10 и новее без разрешения на показ поверх других окон), вызов завершается ошибкой `UI_REQUIRES_FOREGROUND`.
- Node.js и Bun: все методы возвращают Promise; `signal` (AbortSignal) и `timeoutMs` прерывают вызов, в обоих случаях он отклоняется с `CANCELLED`, а у тайм-аута `cause` равен `TimeoutError`; `timeoutMs` должен быть конечным числом больше 0 и не больше 2147483647, дробные значения округляются вверх.
- При ошибке выбрасывается `PdfError` со стабильным `code`, например `PASSWORD_REQUIRED`, `WRONG_PASSWORD` или `PAGE_OUT_OF_RANGE`; `pdf.isAvailable()` заранее проверяет, доступен ли плагин.

### Частые Вопросы

******

#### Можно ли пользоваться им без AutoJs6?

Да. Набор инструментов и просмотрщик работают сами по себе. AutoJs6 нужен только тогда, когда PDF обрабатывают скрипты.

#### Почему плагин запрашивает доступ ко всем файлам?

Он нужен только набору инструментов и просмотрщику, открытому из лаунчера, чтобы читать и записывать файлы, выбранные на экране. AutoJs6 открывает пути, переданные скриптами, и передаёт их плагину как файловые дескрипторы, поэтому скриптам не нужно разрешение плагина на доступ к хранилищу.

#### Есть ли в плагине нативные библиотеки?

Для обработки PDF нативные библиотеки не используются: страницы отрисовывает системный `PdfRenderer`, а остальные функции выполняет PDFBox-Android на чистом Java. Единственная нативная библиотека в пакете - `libandroidx.graphics.path.so` из состава Jetpack Compose.

#### Почему центр плагинов показывает плагин как несовместимый?

Модулю скриптов и пунктам файлового менеджера этого плагина нужен AutoJs6 6.8.1 (внутренняя сборка 6641) или новее. После обновления AutoJs6 плагин можно включить; до этого набор инструментов и просмотрщик работают как обычно.

#### Может ли файловый менеджер AutoJs6 открыть PDF внутри архива?

Да. PDF размером до 512 MiB внутри архива открывается прямо в просмотрщике плагина; файлы большего размера сначала распакуйте.

#### Что делать, если файл из недавних больше не открывается?

Файлы, открытые через системный выбор файлов, сохраняют разрешение на чтение и открываются напрямую даже после перезапуска. Если файл удалён или перемещён либо разрешение отозвано, при нажатии на запись появится сообщение, и она будет удалена из списка; выберите файл заново через "Открыть PDF".

### Разрешения И Безопасность

******

Плагин запрашивает минимально необходимые разрешения:

- Защищённые точки входа: служба возможностей, служба точки входа файлового менеджера и точка активации требуют разрешения плагинов AutoJs6 (`org.autojs.permission.PLUGIN`), поэтому другие приложения не могут вызвать их напрямую. Служба и точка входа просмотрщика для приложений, упакованных AutoJs6, требуют разрешения `org.autojs.plugin.pdf.permission.RUNTIME` (добавляется при упаковке); документы и сеансы просмотрщика, открытые через них, отвечают только создавшему их приложению, а файлы и здесь передаются как файловые дескрипторы.
- Хранилище: файлы скриптов поступают как файловые дескрипторы, поэтому плагин не запрашивает доступ к хранилищу ради скриптов; доступ ко всем файлам используется только для файлов, выбранных вами в наборе инструментов и просмотрщике.
- HTML в PDF: плагин не загружает никакого внешнего содержимого (на сетевые запросы возвращается пустой ответ, локальные файлы и адреса `content:` заблокированы, страница не может переходить по ссылкам); скрипты страницы можно отключить с помощью `javaScript: false`.
- Недавние файлы: файлы, открытые через системный выбор файлов, сохраняют разрешение на чтение, чтобы в следующий раз открываться напрямую, но не более 20 файлов; разрешение освобождается сразу, как только запись вытесняется или удаляется либо список очищается. Файлы, переданные другими приложениями через "Открыть с помощью" или "Поделиться", получают лишь одноразовое разрешение и в недавние файлы не попадают.
- Сеть и пароли: сеть используется только для проверки обновлений; пароли документов используются только в текущей операции и плагином не сохраняются.

### Движок и зависимости

******

Страницы отрисовываются системным `PdfRenderer` из Android; текст, оглавление, изображения, операции со страницами и шифрование выполняет [PDFBox-Android](https://github.com/TomRoush/PdfBox-Android) (Apache-2.0, чистый Java), а шифрование опирается на Bouncy Castle (лицензия в стиле MIT). Обработка PDF не содержит нативных библиотек и не использует нативные движки отрисовки, такие как pdfium или MuPDF.

- `Функция` Скриптам AutoJs6 доступен модуль pdf (также доступен как $pdf): чтение сведений, текста, оглавления и изображений PDF, поиск текста, отрисовка страниц в изображения, объединение, разделение, извлечение, удаление, перестановка и поворот страниц, создание PDF из изображений, текста или HTML, а также шифрование и расшифровка; у каждого метода есть блокирующая форма и форма Async, которые могут сообщать о ходе выполнения и отменяться
- `Функция` Параметр ocr у pdf.text распознаёт отсканированные страницы без текстового слоя с помощью установленного OCR-плагина (ML Kit OCR, Paddle OCR или Rapid OCR)
- `Функция` pdf.view открывает PDF в просмотрщике плагина; скрипты получают события смены страницы и закрытия и могут перейти к странице или закрыть просмотрщик
- `Функция` Скрипты Node.js и Bun тоже могут использовать модуль pdf; его методы возвращают Promise, а вызовы можно прервать с помощью signal или timeoutMs
- `Функция` Приложения, упакованные AutoJs6 6.8.1 или новее, тоже могут использовать модуль pdf, нужное разрешение добавляется при упаковке; открытые ими документы и сеансы просмотрщика отвечают только создавшему их приложению
- `Функция` Просмотрщик: непрерывная прокрутка, масштабирование двумя пальцами, миниатюры, оглавление, подсветка результатов поиска, переход к странице, ввод пароля и ночной режим; открывается из лаунчера, а другие приложения могут передать ему PDF через "Открыть с помощью" или "Поделиться"
- `Функция` Файловый менеджер AutoJs6: нажатие на PDF открывает его в просмотрщике плагина, причём PDF размером до 512 MiB внутри архивов тоже открываются напрямую; меню предлагает объединение, разделение, преобразование в изображения, извлечение текста, шифрование и снятие пароля
- `Функция` Главный экран: инструменты, ход задач, недавние файлы и предоставление доступа ко всем файлам (нужен только набору инструментов)
- `Функция` Недавние файлы запоминают файлы, открытые через системный выбор файлов (до 20), и они открываются напрямую даже после перезапуска; о файле, который удалён или стал недоступен, выводится сообщение, и он удаляется из списка
- `Функция` Набор инструментов из 8 инструментов: объединение, разделение (по диапазонам страниц или каждые n страниц), PDF в изображения (разрешение, формат, страницы), изображения в PDF (размер страницы, ориентация, поля), шифрование, снятие пароля, извлечение текста (в файл TXT), а также поворот, удаление и перестановка страниц по миниатюрам; обработка та же, что и у точек входа файлового менеджера
- `Функция` Задачи набора инструментов выполняются по очереди в активном сервисе и продолжаются после выхода с экрана инструмента; уведомление показывает ход и позволяет отменить, а результаты можно открыть в просмотрщике или отправить
- `Функция` Встроенный файловый браузер позволяет выбирать несколько файлов и создавать папки; системный выбор файлов тоже доступен
- `Функция` Экран настроек: папка вывода по умолчанию (Documents/3-Paper PDF), разрешение по умолчанию для PDF в изображения, язык, ночной режим, цвет темы, значок лаунчера, состояние разрешений, история выпусков и проверка обновлений
- `Функция` Проверка обновлений: вручную на экране настроек или автоматически при открытии главного экрана (не чаще одного раза в 12 часов); сведения о выпусках берутся из официального индекса плагинов
- `Функция` Светлые и тёмные значки для лаунчера и центра плагинов; по умолчанию лаунчер использует адаптивный автоматический значок (следует светлой или тёмной теме системы), а стили адаптивный светлый, адаптивный тёмный и прозрачный фон уже встроены, выбрать их можно на экране настроек
- `Функция` Один APK для всех ABI: обработка PDF не содержит нативных библиотек; единственная нативная библиотека входит в Jetpack Compose и выровнена по страницам памяти 16 KB
